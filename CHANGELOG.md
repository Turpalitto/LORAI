# CHANGELOG — LORAI

## [1.3.0] — 2026-10-07 — поиск: embeddings, маршрутизация по разделам, корпус без дублей

Полные измерения и оговорки: `docs/RETRIEVAL_EVAL.md`, решение: DECISIONS #26.

### Исправлено
- **Ложные отказы на реальных ЛОР-вопросах: 20 % → 0 %.** Домен-гейт не знал «ё» («ребёнка» ≠ «ребен»), не имел лексики «эпиглоттит/круп/стридор/тризм/глотание/оталгия», а «паратонзиллярный» перестал находиться при переходе на поиск с начала слова. Теперь: нормализация «ё», расширенный словарь, длинные маркеры — подстрокой, короткие — с начала слова. Вне-доменные вопросы по-прежнему отсекаются 100 %.
- **Корпус поиска на 84 % состоял из дублей** (1304 из 1599 чанков — `general`, разделы покрывали ~17 % текста): из-за этого в топ-6 попадали обзорные куски, и модель отвечала «в контексте нет информации». Индекс пересобран из PDF (`scripts/reindex_corpus.py`): документ покрыт ровно один раз, чанки помечены разделом и реальными страницами. SQLite не тронут, бэкап прежнего индекса сохранён.
- `VECTOR_BACKEND` из `.env` игнорировался: стор читал только переменные окружения, а не настройки pydantic.

### Добавлено
- **Получить по вопросу нужный раздел протокола**: `section_hint()` в `rag/retriever.py` + `section_boost` и ограничение обзорных чанков (`GENERAL_CHUNK_CAP`) в поиске. Единая точка `retrieve()` — приложение и замер используют один код.
- **Эмбеддинги как рабочий бэкенд**: `intfloat/multilingual-e5-base` (`VECTOR_BACKEND=embeddings`), префиксы query/passage, персистентный индекс, устройство MPS/CUDA/CPU, кэш модели внутри проекта (`data/hf_cache`), честный откат на TF-IDF с причиной в `/health`.
- **`effective_threshold()`**: порог скора зависит от шкалы бэкенда (TF-IDF 0.12 / эмбеддинги 0.80) — у e5 даже нерелевантный текст даёт 0.83–0.85.
- **Замер как часть проекта**: `data/eval/lor_retrieval_golden.json` (30 ЛОР-вопросов + 6 вне-доменных), `scripts/eval_retrieval.py` (recall@k, MRR, покрытие разделов, «протокол+раздел», отказы, скоры), `scripts/eval_answers.py` (ответ-уровень на реальных вызовах LLM), `scripts/reindex_corpus.py`, `scripts/reindex_embeddings.py`.
- `/health` отдаёт состояние поиска (`retrieval.backend`, `vectors_indexed`); дашборд показывает врачу, работает ли семантический поиск.
- Тесты: backend 90 (маршрутизация, honesty-score при бусте, откат бэкенда, целостность золотого набора).

### Добавлено во втором проходе (hold-out + аудит разметки)
- **Hold-out набор** `data/eval/lor_retrieval_holdout.json` (22 вопроса в разговорной формулировке + 5 вне-доменных): на нём nothing не настраивалось — проверка обобщения.
- **LLM-судья** в `scripts/eval_answers.py --judge`: структурированная оценка ответа (отвечает ли по существу, опирается ли только на выдержки) вместо регулярки.
- **Аудит разметки разделов** `scripts/check_section_labels.py`: найдено «дребезжание» заголовков (80 переключений на документ) и попадание библиографии в раздел `prevention`. Детектор заголовков стал строгим (строка целиком = название главы); лексическое совпадение: treatment 99 %, diagnostics 88 %, prevention 21 % → 72 %.
- **Фильтр вёрстки и библиографии** при сборке индекса: колонтитулы, крошки, URL, номера страниц и глава «Источники и литература» в индекс не попадают (индекс 1899 → 1084 чанка, клинический текст сохранён на 99 %).
- **Гибридное ранжирование** `HYBRID_WEIGHT=0.15` (эмбеддинги + лексика) — включено по out-of-sample результату: recall@6 0.727 → 0.818 на hold-out.
- **Порог эмбеддингов 0.75** вместо 0.80: убирает ложные отказы двух реальных вопросов (скор 0.797), не влияя на отсечение вне-доменных.

## [1.2.0] — 2026-10-07 — доводка до топ-уровня (SSE, чек-листы, сессия врача)

Подробности с измерениями: `docs/UPGRADE_1.2_REPORT.md`.

### Исправлено (реальные дефекты)
- **SSE перестал быть бутафорией**: `/chat/stream` отдавал `list(answer_stream(...))` — весь ответ собирался до старта отправки. Теперь ленивый `StreamingResponse`: живой TTFB **7 мс** вместо полного времени генерации (3.4 с), 184+ токен-события.
- **Кнопка «Остановить» действительно обрывает поток**: слушатель отмены снимался на приходе заголовков ответа, из-за чего `abort()` не влиял на тело. Отмена/таймер теперь живут до конца чтения; частичный текст сохраняется.
- **Чек-листы всех 22 КР были мусором** (колонтитулы, URL MedElement, даты, `[13;15;16]`), потому что `diagnostics.*` при ингесте не заполняются. Генератор переписан на экстрактивный разбор текста: ~20 % → **0.6 %** мусора, 324 осмысленных пункта, флаги `auto_generated`/`needs_source`.
- Живой стенд был устаревшим: `/chat/stream` → 404, CORS без дев-порта `:5200`.
- `store.num()` возвращал `0` вместо запасного значения для пустого ключа.

### Добавлено
- `POST /chat/stream` (клинический текст вопроса больше не попадает в URL/логи); GET сохранён.
- `GET /favorites` обогащён `nosology`/`title`/`icd10_codes`.
- Чат: диалог с историей, markdown-рендер ответа, копирование ответа и источников, `Ctrl/⌘+Enter`, `Esc`, «Новый диалог», автопрокрутка.
- Сессия врача: страница `#/login`, чип с ролью и сроком сессии в шапке, выход, «нужен вход» вместо 401-плашек в истории/избранном/админке.
- Чек-лист: сохранение отметок между визитами, прогресс, «отметить все»/«сбросить», копирование, печать.
- Админка: фильтр документов, отметка «проверено» (PATCH), авто-статистика, форма входа по правилам браузера.
- Ленивая загрузка маршрутов: главный бандл 185 → 161.85 КБ (gzip 53.7), 11 чанков по требованию.
- Доступность: заголовок вкладки по разделу, фокус на содержимом, честный skip-link, тосты `aria-live`, инлайн-скрипт темы (без вспышки).
- Тесты: backend 61 → **72**, frontend 4 → **35** (включая регресс на обрыв потока, который падает на старом коде).
