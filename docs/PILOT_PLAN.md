# PILOT PLAN — внутренний пилот ЛОРАИ (PWA)

## Рамка
- Участники: 3–5 ЛОР-врачей одной клиники (включая 1 администратора, который грузит PDF).
- Длительность: 14 календарных дней с момента выдачи ссылки.
- Режим: PWA на личных Android-телефонах врачей (установка через Chrome → «Установить»).
  LLM: включён real provider (см. GO_LIVE_CHECKLIST) либо честно зафиксированный mock.
- Поддержка: общий чат/канал + кнопка «Сообщить о проблеме» в приложении
  (авто-прикрепляет вопрос, ответ, score, session — без персональных данных).

## Что меряем (метрики успеха — снимать в конце каждой недели из /admin/stats и БД)

| Метрика | Источник | Цель пилота |
|---|---|---|
| Активные врачи (≥3 запроса/нед) | QueryLog по дням | ≥3 из 5 |
| Доля честных отказов («нет данных») | usage_stats.refusal_rate | <15% (выше = пробелы базы → догрузить КР) |
| Оценки ответов 👍/(👍+👎) | feedback | ≥70% |
| Сообщений «о проблеме» без дублей | feedback.comment | <5 уникальных, все разобраны |
| Среднее время ответа чата | avg_latency_ms | <8 с (mock) / <20 с (real LLM) |
| Загрузок PDF админом без помощи разработчика | опрос + документы в БД | 100% самостоятельно |

## Недельный ритм
- День 1: установка PWA по DEVICE_TEST_PROTOCOL, тестовый вопрос каждым врачом.
- День 7: срез метрик, разбор «нет данных» и reports, догрузка недостающих КР.
- День 14: финальный срез + 15-минутные интервью (что мешало на приёме?).

## Критерии перехода пилот → внедрение
1. Все метрики из таблицы — в цели 2 недели подряд.
2. Ноль открытых reports с severity «неверная дозировка/назначение».
3. DEVICE_TEST_PROTOCOL пройден минимум на 2 разных моделях телефонов.
4. Реальные PDF (≥80% нозологий приёма) загружены, needs_review разобран.
5. Назначен ответственный за базу (кто грузит новые КР и смотрит knowledge_gaps).

## Стоп-критерии (пилот прерывается)
- Любой случай, когда врач последовал неверной цифре из ответа (разбор в тот же день).
- refusal_rate >30% неделю подряд (база не покрывает приём — пилот бессмыслен).
