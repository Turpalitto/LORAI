# LORAI 1.2.0 — доводка до топ-уровня (сессия 2026-10-07)

Всё ниже проверено реальным запуском: живой backend на `:8000` (OpenRouter),
frontend на `:5200`, браузер через CDP. Скриншоты — `docs/screens/`.

## 1. Что было сломано по-настоящему

| # | Дефект | Доказательство |
|---|--------|----------------|
| 1 | **SSE не стримил.** `/chat/stream` делал `list(answer_stream(...))` — ответ уходил целиком после генерации, «печать токенов» была бутафорией. | live TTFB до фикса = полное время ответа; после фикса TTFB **0.007 с**, всего 3.43 с, 184 события `token` |
| 2 | **Кнопка «Остановить» не останавливала.** Слушатель отмены снимался, как только `fetch` отдавал заголовки (а он резолвится до тела), поэтому `abort()` уже ни на что не влиял. | до фикса: state `streaming`, текст продолжал расти (0 → 419 симв.); после: state `stopped`, рост прекращён, частичный текст сохранён |
| 3 | **Все 22 чек-листа приёма были мусором.** `diagnostics.complaints/anamnesis/physical_exam/lab_tests/instrumental_tests` при ингесте никогда не заполняются, поэтому генератор резал сырой PDF на строки: в пункты приёма попадали URL `medelement`, даты печати, колонтитулы и маркеры `[13;15;16]`. | аудит по API: 22/22 документа в raw-fallback, ~20 % пунктов — мусор |
| 4 | **Клинический вопрос уходил в URL.** `GET /chat/stream?query=...` писал текст обращения врача в access-логи, прокси и историю браузера. | добавлен `POST /chat/stream` |
| 5 | **Стенд был устаревшим.** Рабочий процесс на `:8000` не знал `/chat/stream` (404) и не имел CORS для дев-порта `:5200`. | `curl /chat/stream` → 404 до перезапуска |

## 2. Что добавлено и улучшено

### Backend
- `POST /chat/stream` (JSON-тело) — предпочтительный путь, GET сохранён для совместимости.
- **Настоящий ленивый SSE**: `StreamingResponse` поверх генератора, `latency_ms`/`record_latency` считаются до события `done`, заголовки `Cache-Control: no-cache`, `X-Accel-Buffering: no`.
- `GET /favorites` обогащён `nosology`/`title`/`icd10_codes` — избранное больше не показывает врачу `doc_id`.
- **Генератор чек-листа переписан**: склейка переносов вёрстки в предложения, вырезание колонтитулов/URL/дат/маркеров библиографии, снятие методических шапок («Уровень убедительности рекомендаций…»), классификация по блокам приёма (жалобы/анамнез/осмотр/лабораторно/инструментально), дедуп, ограничение длины пункта (≤260 симв.), флаги `auto_generated` / `needs_source` и честная пометка «сверьте с оригиналом».
- Инвариант «ничего не додумываем» сохранён: пункты только экстрактивные, при отсутствии текста чек-лист пуст и UI отправляет врача к оригиналу.

### Frontend
- **Чат-диалог**: история вопросов и ответов в одном экране, серверная память диалога, автопрокрутка (пока врач не отлистал вверх), `Ctrl/⌘+Enter` — отправить, `Esc` — остановить, «Новый диалог».
- **Markdown ответа** собственным безопасным парсером (заголовки, списки, **жирный**, `код`) — без `dangerouslySetInnerHTML`, без внешних зависимостей.
- **Копирование** ответа, списка источников, чек-листа, шаблонов, результатов калькуляторов.
- **Сессия врача**: страница `#/login`, чип в шапке с ролью и сроком сессии, выход, понятные 401 вместо молчаливых ошибок; история/избранное/админка показывают «нужен вход» вместо красной плашки.
- **Чек-лист**: отметки сохраняются в браузере (переживают перезагрузку), прогресс «отмечено N из M», «Отметить все»/«Сбросить», копирование текстом, печать.
- **Админка**: форма входа с семантикой браузера, фильтр документов, отметка «проверено» одним нажатием, авто-загрузка статистики, аналоги без потери пароля.
- **Производительность**: маршруты грузятся лениво — главный бандл 185 → **161.85 КБ (gzip 53.7)**, остальное разбито на 11 чанков (админка, инструменты, чат и т.д. грузятся по требованию).
- **Доступность/полировка**: заголовок вкладки по разделу, перевод фокуса на содержимое при смене раздела, честный skip-link, `aria-*` на состояниях, тосты с `aria-live`, защита от «вспышки светлой темы» инлайн-скриптом до первой отрисовки, безопасный `localStorage` (приватный режим Safari не роняет экран).

## 5. Честные ограничения (не закрыто в этой сессии)

1. **Качество поиска важнее косметики.** На живом стенде порог TF-IDF 0.12 и
   отказы: на выборке сессии (`/admin/stats`) отказов 35.7 %, и даже на
   in-domain вопрос про острый средний отит модель отвечала «в контексте нет
   информации», хотя в базе 6 источников. Это ограничение retrieval (TF-IDF
   fallback без embeddings), а не интерфейса. Следующий шаг — реальные
   embeddings + порог 0.75 (ROADMAP, DECISIONS #1).
2. Структурированные подразделы диагностики при ингесте по-прежнему не
   заполняются — чек-листы собираются из текста автоматически (помечено в UI).
   Полное лечение — LLM-структурирование/ручная правка при загрузке КР.
3. `/favorites` обогащается сканом метаданных всех документов (нормально при 22 КР,
   при росте базы — вынести в SQL-join).
4. PWA-установка и офлайн на физическом Android не проверены (нет устройства).
5. Flutter/mobile-фаза по-прежнему заблокирована (нет SDK) — вне web-стека.
