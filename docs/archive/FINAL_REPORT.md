## LORAI 1.3.0 — качество поиска: embeddings, разделы, корпус без дублей (2026-10-07, отчёт: docs/RETRIEVAL_EVAL.md)

- Сначала построен замер (золотой набор 30 ЛОР-вопросов + 6 вне-доменных, два
  харнесса: `scripts/eval_retrieval.py` и `scripts/eval_answers.py`), затем —
  изменения по его результатам. Не наоборот.
- Измеренные дефекты: ложные отказы 20 % (домен-гейт без «ё» и без лексики
  «эпиглоттит/круп/тризм/глотание/оталгия»); корпус на 84 % из дублей `general`
  (разделы покрывали ~17 % текста) — модель отвечала «в контексте нет информации».
- Что сделано: embeddings `intfloat/multilingual-e5-base` как рабочий бэкенд с
  честным откатом на TF-IDF; маршрутизация вопроса на нужную главу протокола
  (`section_hint` + буст раздела + ограничение обзорных чанков); пересборка
  индекса из PDF без дублей (SQLite не тронут, бэкап сохранён); свой порог скора
  для каждого бэкенда; состояние поиска в `/health` и на дашборде.
- Измеренный итог (одна метрика, до/после): «протокол + нужный раздел» 0.633 →
  **0.900**, покрытие разделов 0.667 → **1.000**, recall@1 0.767 → **0.800**,
  MRR 0.876 → **0.926**, ложные отказы 0.200 → **0.000**, вне-доменные

  0.625 → **0.917**, ответов «нет информации» — **0**.
- Проверки: backend **90/90** (+6 тестов маршрутизации/бэкендов/целостности

  живой стенд на embeddings: TTFB стрима 2.5 мс, 313 токен-событий.

### 1.3.0, второй проход: hold-out, аудит разметки, фильтр библиографии (2026-10-07)

- **Hold-out набор** (`data/eval/lor_retrieval_holdout.json`, 22 вопроса в разговорной
  формулировке + 5 вне-доменных) показал, что in-sample цифры были оптимистичны:
  recall@6 0.727 против 0.900. Добавлен **LLM-судья** (`eval_answers.py --judge`).
- **Аудит разметки разделов** (`scripts/check_section_labels.py`) нашёл настоящие
  дефекты: «дребезг» заголовков (80 переключений раздела на документ) и главу
  «Источники и литературы», не распознававшуюся как библиография, — ~140 чанков
  ссылок числились разделом `prevention` и могли попадать в «источники» ответа.
  Детектор заголовков стал строгим (строка целиком = название главы), в индекс
  больше не попадают колонтитулы, URL и библиография: индекс 1899 → 1084 чанка при
  сохранении 99 % клинического текста.
- **Финальная конфигурация**: embeddings + маршрутизация по разделам + гибридное
  ранжирование (`HYBRID_WEIGHT=0.15`, включено по out-of-sample результату
  recall@6 0.727 → 0.818) + порог эмбеддингов 0.75 (убирает ложные отказы при
  скорах 0.797, не влияя на отсечение вне-доменных).
- **Итог на hold-out** (рабочая конфигурация): recall@6 **0.864**, MRR **0.908**,
  recall@1 **0.727**, покрытие разделов **1.000**, «протокол+раздел» **0.864**,
  ложные отказы **0.000**, вне-доменные отсекаются **1.000**. Ответ-уровень:
  21/22 с содержанием, 0 отказов, судья — «по существу» 0.77, «опирается только на
  выдержки» **0.91** (разброс между прогонами ±7 п.п.). TF-IDF на тех же вопросах
  отказывает в **64 %** случаев — эмбеддинги обязательны.
- Проверки: backend **90/90**, frontend **35/35**, `tsc` + build чисто, e2e **7/7**,
  живой стенд: `retrieval: embeddings, vectors_indexed: 1084`, TTFB стрима 9 мс,
  359 токен-событий; на вопрос «частые ангины: когда убирать миндалины» — ответ про
  тонзиллэктомию с источниками.
